# Reproduction notes — ETH/UCY five-architecture audit

This documents how the per-model trajectory dumps in `../dumps/ethucy/` were produced on a
rented GPU box (2× RTX 4090, Ubuntu 24.04, CUDA 13 host driver). All analysis then runs on a
laptop via `../trajectory_eval` and `../experiments/analyze_ethucy.py`.

## Environment
- One conda/micromamba env (`tp`): Python 3.9, **PyTorch 2.2.2 + cu121** (the 4090's sm_89
  needs torch >= 2.0), `numpy==1.23.5` (pin <2 for the older repos), scipy, pandas, matplotlib,
  pyyaml, yacs, dill, ncls, orjson, pyquaternion, easydict, glob2, tensorboardX, gdown.
- `env.sh` sets `MAMBA_ROOT_PREFIX`, a `wandb` no-op stub on `PYTHONPATH`, and cache dirs.
  `build_env.sh` builds the env.

## Datasets
- ETH/UCY processed `.pkl`s are generated by Trajectron++'s
  `experiments/pedestrians/process_data.py` (5 scenes × {train,val,test}); BiTraP, SGNet, and
  Trajectron++ all consume these. Social GAN and AgentFormer ship their own ETH/UCY data.

## Standardized dump
Every model is patched/wrapped to emit one `.npz` per scene with **raw** arrays:
`pred (N,K,T,2)`, `gt (N,T,2)`, `track_id`, `meta_json` — all in world meters, K=20, T=12.
`trajectory_eval` is the single source of truth for every metric.

## Per-model patches (minimal, dump-only + torch-2.2 compat)
- **BiTraP** (`umautobots/bidireaction-trajectory-prediction`): `patch_bitrap.py` adds the raw
  dump in `bitrap/engine/trainer.py::inference` (env `TRAJCRIT_DUMP`) and per-run seeding in
  `tools/train.py`; the per-epoch inference call was changed to fire only on the final epoch.
  Pass `--gpu N` (train.py overrides `CUDA_VISIBLE_DEVICES`). Trained 50 epochs/scene.
- **SGNet** (`ChuhuaW/SGNet.pytorch`): `patch_sgnet.py` adds the dump in
  `lib/utils/ethucy_train_utils_cvae.py::test`. Run `tools/ethucy/train_cvae.py` with
  **uppercase** `--dataset` (ETH/HOTEL/...) — the feature-extractor registry is keyed uppercase,
  while the data path uses `.lower()`. Trained 50 epochs/scene. ~8 GB/job → cap concurrency.
- **Trajectron++** (`StanfordASL/Trajectron-plus-plus`): no repo edit; `tpp_dump.py` loads a
  trained checkpoint, calls `predict(num_samples=20)`, and assembles dumps via
  `prediction_output_to_trajectories` (predict returns `(1,K,T,2)` per agent — drop the batch
  axis). Trained 1 model/scene from the released `*_vel/config.json`.
- **Social GAN** (`agrimgupta92/sgan`): pretrained weights (`download_models.sh`). `sgan_dump.py`
  loads the generator and samples 20 trajectories. torch-2.2 fix: `.view(` → `.reshape(` in
  `sgan/models.py` (non-contiguous tensors); `AttrDict` replaced by a 2-line shim; `g.train()`
  per the official eval. Also writes a matched constant-velocity dump (`ConstVelSG_*`) on its
  own tracks.
- **AgentFormer** (`Khrylx/AgentFormer`): pretrained weights (Google Drive, user-authorized).
  `af_dump.py` mirrors `test.py` but accumulates arrays. torch-2.2 fix: shim `_LinearWithBias`
  (removed from modern `torch.nn.modules.linear`) in `model/agentformer_lib.py`. Uses the
  standard ETH/UCY test set (same tracks as the Trajectron-data CV).

## Baselines & orchestration
- `cv_baseline.py` computes constant-velocity / constant-acceleration dumps from each scene's
  observed history (last-step displacement extrapolated; uses only the past).
- `orchestrate_ethucy.sh` (BiTraP seed grid), `orchestrate_tpp.sh` (Trajectron++),
  `orchestrate_sgnet3.sh` (SGNet, memory-capped) run the campaigns and dump per scene.

## Analysis (laptop)
`python experiments/analyze_ethucy.py` reads `dumps/ethucy/*.npz`, computes best-of-K minADE,
the deployable single-sample error, oracle inflation, constant-velocity comparison, and the
heavy-tail statistics, and writes `outputs/results_ethucy.json` + the two figures.
